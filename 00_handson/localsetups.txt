## Project 0.1 — Local Cloud Development Setup

### Overview
Install and configure all tools needed for the rest of the roadmap. Use LocalStack to emulate AWS services locally so you can experiment without incurring costs.

---

### Hands-on Steps

#### Step 1 — Install Core Tools

```bash
# Docker Desktop (includes Docker Compose)
# Download from: https://www.docker.com/products/docker-desktop

# Verify
docker --version
docker compose version

# AWS CLI v2
# Download from: https://docs.aws.amazon.com/cli/latest/userguide/install-cliv2.html
aws --version

# Terraform
# Download from: https://developer.hashicorp.com/terraform/downloads
terraform --version

# Git
git --version
```

#### Step 2 — Configure AWS CLI for LocalStack

```bash
# Create a fake profile for LocalStack (never use real credentials locally)
aws configure --profile localstack
# AWS Access Key ID: test
# AWS Secret Access Key: test
# Default region: us-east-1
# Default output format: json
```

#### Step 3 — Start LocalStack with Docker Compose

Create `docker-compose.yml`:

```yaml
version: "3.8"
services:
  localstack:
    image: localstack/localstack:latest
    ports:
      - "4566:4566"
    environment:
      - SERVICES=s3,lambda,apigateway,dynamodb,iam,logs
      - DEBUG=1
      - LAMBDA_EXECUTOR=docker
      - DOCKER_HOST=unix:///var/run/docker.sock
    volumes:
      - "/var/run/docker.sock:/var/run/docker.sock"
      - "./localstack-data:/var/lib/localstack"
```

```bash
docker compose up -d
# Verify LocalStack is running
curl http://localhost:4566/_localstack/health
```

#### Step 4 — Test LocalStack with S3

```bash
# Create a bucket
aws --endpoint-url=http://localhost:4566 --profile localstack s3 mb s3://test-bucket

# Upload a file
echo "Hello LocalStack" > test.txt
aws --endpoint-url=http://localhost:4566 --profile localstack s3 cp test.txt s3://test-bucket/

# List bucket contents
aws --endpoint-url=http://localhost:4566 --profile localstack s3 ls s3://test-bucket/
```

#### Step 5 — Deploy a Lambda Function Locally

Create `hello_lambda.py`:

```python
import json

def handler(event, context):
    return {
        "statusCode": 200,
        "body": json.dumps({"message": "Hello from LocalStack Lambda!"})
    }
```

```bash
# Zip the function
zip hello_lambda.zip hello_lambda.py

# Create Lambda
aws --endpoint-url=http://localhost:4566 --profile localstack lambda create-function \
  --function-name hello-lambda \
  --runtime python3.11 \
  --handler hello_lambda.handler \
  --role arn:aws:iam::000000000000:role/lambda-role \
  --zip-file fileb://hello_lambda.zip

# Invoke Lambda
aws --endpoint-url=http://localhost:4566 --profile localstack lambda invoke \
  --function-name hello-lambda \
  output.json

cat output.json
```

#### Step 6 — Create a DynamoDB Table Locally

```bash
aws --endpoint-url=http://localhost:4566 --profile localstack dynamodb create-table \
  --table-name Users \
  --attribute-definitions AttributeName=userId,AttributeType=S \
  --key-schema AttributeName=userId,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST

# Insert an item
aws --endpoint-url=http://localhost:4566 --profile localstack dynamodb put-item \
  --table-name Users \
  --item '{"userId": {"S": "user-001"}, "name": {"S": "Alice"}}'

# Query it
aws --endpoint-url=http://localhost:4566 --profile localstack dynamodb scan \
  --table-name Users
```

## Project 0.2 — Linux Foundations Lab

### Overview
Practice Linux administration in a Docker container. No cloud account needed.

---

### Hands-on Steps

#### Step 1 — Start a Linux Container

```bash
# Run Ubuntu container interactively
docker run -it --name linux-lab ubuntu:22.04 /bin/bash
```

#### Step 2 — File System Navigation

```bash
# Inside the container
pwd
ls -la /
ls -la /etc
ls -la /var/log

# Create directory structure
mkdir -p /opt/myapp/{logs,config,data}
ls -la /opt/myapp/
```

#### Step 3 — User & Permission Management

```bash
# Create a new user
useradd -m -s /bin/bash appuser
passwd appuser

# Create a group
groupadd appgroup
usermod -aG appgroup appuser

# Set file permissions
touch /opt/myapp/config/app.conf
chown appuser:appgroup /opt/myapp/config/app.conf
chmod 640 /opt/myapp/config/app.conf

# Verify
ls -la /opt/myapp/config/
```

#### Step 4 — Install and Configure Nginx

```bash
apt-get update && apt-get install -y nginx

# Start Nginx
service nginx start

# Verify
curl http://localhost

# Edit default page
echo "<h1>Hello from Linux Lab</h1>" > /var/www/html/index.html
curl http://localhost
```

#### Step 5 — Process Management

```bash
# View running processes
ps aux
ps aux | grep nginx

# View system resources
top  # press q to quit
free -h
df -h

# Kill a process
kill -9 <PID>
```

#### Step 6 — Log Analysis

```bash
# View Nginx access logs
tail -f /var/log/nginx/access.log

# Search logs
grep "404" /var/log/nginx/access.log
grep "GET" /var/log/nginx/access.log | wc -l

# System logs
journalctl -u nginx
```

#### Step 7 — Cron Jobs

```bash
# Edit crontab
crontab -e

# Add a job that runs every minute
* * * * * echo "$(date): cron ran" >> /opt/myapp/logs/cron.log

# Verify after 1 minute
cat /opt/myapp/logs/cron.log
```

#### Step 8 — SSH Setup (between two containers)

```bash
# In a new terminal, start a second container
docker run -d --name ssh-server --hostname server ubuntu:22.04 sleep infinity

# Install SSH on both
docker exec ssh-server apt-get install -y openssh-server

# Generate key pair on client
ssh-keygen -t rsa -b 4096 -f ~/.ssh/lab_key -N ""

# Copy public key to server
docker exec ssh-server mkdir -p /root/.ssh
docker cp ~/.ssh/lab_key.pub ssh-server:/root/.ssh/authorized_keys
```

## Project 0.3 — Git & GitHub Workflow

### Overview
Set up a real Git workflow that you'll use for every project in this roadmap.

---

### Hands-on Steps

#### Step 1 — Initialize Repository

```bash
mkdir aws-handson-projects
cd aws-handson-projects
git init
git config user.name "Your Name"
git config user.email "your@email.com"
```

#### Step 2 — Create Standard Project Structure

```bash
mkdir -p project-01-static-website/{terraform,docs,screenshots}
touch project-01-static-website/README.md
touch project-01-static-website/terraform/main.tf
touch .gitignore
```

Create `.gitignore`:

```gitignore
# Terraform
.terraform/
*.tfstate
*.tfstate.backup
.terraform.lock.hcl
terraform.tfvars

# AWS credentials
.aws/
*.pem
*.key

# OS
.DS_Store
Thumbs.db

# IDE
.vscode/
.idea/
```

#### Step 3 — Branching Workflow

```bash
# Main branch is always deployable
git checkout -b main

# Create feature branch for each project
git checkout -b feature/project-01-static-website

# Make changes
echo "# Static Website Project" > project-01-static-website/README.md
git add .
git commit -m "feat: add project 01 static website structure"

# Push to GitHub
git remote add origin https://github.com/yourusername/aws-handson-projects.git
git push -u origin feature/project-01-static-website
```

#### Step 4 — Pull Request Workflow

```bash
# On GitHub: create PR from feature branch to main
# Add description:
# - What this project does
# - Architecture used
# - Services used
# - Cost estimate

# After review, merge to main
git checkout main
git pull origin main
git branch -d feature/project-01-static-website
```

#### Step 5 — GitHub Actions Basics

Create `.github/workflows/validate.yml`:

```yaml
name: Validate Terraform

on:
  pull_request:
    paths:
      - '**/*.tf'

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: hashicorp/setup-terraform@v3
      - name: Terraform Init
        run: terraform init
        working-directory: ./project-01-static-website/terraform
      - name: Terraform Validate
        run: terraform validate
        working-directory: ./project-01-static-website/terraform
```

#### Step 6 — Commit Message Convention

```bash
# Use conventional commits
git commit -m "feat: add S3 bucket for static website"
git commit -m "fix: correct S3 bucket policy"
git commit -m "docs: add architecture diagram"
git commit -m "chore: update .gitignore"
git commit -m "refactor: extract VPC into terraform module"
```

## Project 0.4 — AWS Cost & Billing Fundamentals

### Overview
Set up billing protection before doing anything else in AWS. This is the most important project in Stage 0.

---

### Hands-on Steps

#### Step 1 — Enable Billing Alerts

1. Log in to AWS Console as root user
2. Go to **Account** → **Billing preferences**
3. Enable:
   - "Receive Free Tier Usage Alerts"
   - "Receive Billing Alerts"
4. Save preferences

#### Step 2 — Create a CloudWatch Billing Alarm

```bash
# Via AWS CLI
aws cloudwatch put-metric-alarm \
  --alarm-name "billing-alert-10usd" \
  --alarm-description "Alert when estimated charges exceed $10" \
  --metric-name EstimatedCharges \
  --namespace AWS/Billing \
  --statistic Maximum \
  --period 86400 \
  --threshold 10 \
  --comparison-operator GreaterThanThreshold \
  --dimensions Name=Currency,Value=USD \
  --evaluation-periods 1 \
  --alarm-actions arn:aws:sns:us-east-1:YOUR_ACCOUNT_ID:billing-alerts \
  --region us-east-1
```

#### Step 3 — Create SNS Topic for Billing Alerts

```bash
# Create SNS topic
aws sns create-topic --name billing-alerts --region us-east-1

# Subscribe your email
aws sns subscribe \
  --topic-arn arn:aws:sns:us-east-1:YOUR_ACCOUNT_ID:billing-alerts \
  --protocol email \
  --notification-endpoint your@email.com \
  --region us-east-1

# Confirm the subscription via email
```

#### Step 4 — Create AWS Budget

```bash
# Create a $20/month budget with alerts at 50%, 80%, 100%
aws budgets create-budget \
  --account-id YOUR_ACCOUNT_ID \
  --budget '{
    "BudgetName": "monthly-aws-budget",
    "BudgetLimit": {"Amount": "20", "Unit": "USD"},
    "TimeUnit": "MONTHLY",
    "BudgetType": "COST"
  }' \
  --notifications-with-subscribers '[
    {
      "Notification": {
        "NotificationType": "ACTUAL",
        "ComparisonOperator": "GREATER_THAN",
        "Threshold": 80,
        "ThresholdType": "PERCENTAGE"
      },
      "Subscribers": [{"SubscriptionType": "EMAIL", "Address": "your@email.com"}]
    }
  ]'
```

#### Step 5 — Set Up Cost Allocation Tags

```bash
# Activate cost allocation tags in Billing Console
# Then tag all resources you create:
aws ec2 create-tags \
  --resources i-1234567890abcdef0 \
  --tags Key=Project,Value=handson Key=Stage,Value=stage-01 Key=Owner,Value=yourname
```

#### Step 6 — Explore Cost Explorer

1. Go to **Billing** → **Cost Explorer**
2. Enable Cost Explorer (first time only, takes 24h)
3. View:
   - Cost by service
   - Cost by region
   - Free tier usage
4. Set up a monthly cost report via email

#### Step 7 — Free Tier Tracking

Key free tier limits to know:

| Service | Free Tier Limit |
|---------|----------------|
| EC2 | 750 hrs/month t2.micro or t3.micro |
| S3 | 5 GB storage, 20K GET, 2K PUT |
| RDS | 750 hrs/month db.t2.micro or db.t3.micro |
| Lambda | 1M requests/month, 400K GB-seconds |
| DynamoDB | 25 GB storage, 25 WCU, 25 RCU |
| CloudWatch | 10 metrics, 1M API requests |

### Terraform Code

```hcl
# billing_alarm.tf

provider "aws" {
  region = "us-east-1"
}

resource "aws_sns_topic" "billing_alerts" {
  name = "billing-alerts"
}

resource "aws_sns_topic_subscription" "billing_email" {
  topic_arn = aws_sns_topic.billing_alerts.arn
  protocol  = "email"
  endpoint  = var.alert_email
}

resource "aws_cloudwatch_metric_alarm" "billing_alarm" {
  alarm_name          = "billing-alert-${var.threshold_usd}usd"
  alarm_description   = "Alert when estimated charges exceed $${var.threshold_usd}"
  metric_name         = "EstimatedCharges"
  namespace           = "AWS/Billing"
  statistic           = "Maximum"
  period              = 86400
  threshold           = var.threshold_usd
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 1
  alarm_actions       = [aws_sns_topic.billing_alerts.arn]

  dimensions = {
    Currency = "USD"
  }
}

variable "alert_email" {
  description = "Email address for billing alerts"
  type        = string
}

variable "threshold_usd" {
  description = "Billing threshold in USD"
  type        = number
  default     = 10
}

output "sns_topic_arn" {
  value = aws_sns_topic.billing_alerts.arn
}
```
