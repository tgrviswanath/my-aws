1 Project Overview

What this project does and key concepts

This project automates Terraform infrastructure management using GitHub Actions CI/CD with OIDC authentication — the industry-standard approach where no AWS credentials are ever stored in GitHub. Every infrastructure change goes through a reviewed pull request, and drift from manual console changes is detected daily.

CI/CD Workflow

Developer opens PR → GitHub Actions: terraform fmt + validate + plan → Plan output posted as PR comment → Reviewer approves PR → Merge to main → GitHub Actions: terraform apply (exact saved plan) → Infrastructure updated in AWS automatically → Daily: drift detection catches manual changes

11 Phase 6 — Drift Detection

terraform-drift.yml — Detecting manual infrastructure changes

⏰ Trigger: Daily 8am UTC + Manual workflow_dispatch

Drift Simulation

Two manual changes were made outside Terraform to simulate real-world drift:

ChangeHowEffect
SNS topic deletedAWS Console → SNS → handson-pipeline-alerts → DeleteTerraform state says it exists, AWS says it doesn't
Manual tag added to S3 bucketAWS Console → S3 → bucket → Tags → Add ManualChange=trueTerraform config doesn't have this tag

First Run — Exit Code Bug

Terraform plan detected drift: # aws_sns_topic.pipeline_alerts has been deleted # aws_s3_bucket.app — ManualChange tag added Terraform exit code: 0 ← BUG: should be 2 ✅ No drift detected ← WRONG result
Root Cause: terraform_wrapper: true The hashicorp/setup-terraform@v3 action wraps the Terraform binary by default (terraform_wrapper: true). This wrapper intercepts stdout/stderr for output capture but also swallows the real exit code — always returning 0 to the shell. PIPESTATUS[0] captured the wrapper's exit code (0) instead of Terraform's real exit code (2).

Fix — Disable terraform_wrapper

- name: Setup Terraform
  uses: hashicorp/setup-terraform@v3
  with:
    terraform_version: ${{ env.TF_VERSION }}
    terraform_wrapper: false   # Must be false to get real exit codes

Second Run — Drift Correctly Detected

Acquiring state lock. This may take a few moments... Note: Objects have changed outside of Terraform # aws_sns_topic.pipeline_alerts has been deleted # aws_s3_bucket.app will be updated in-place ~ tags = { - "ManualChange" = "true" -> null } Plan: 1 to add, 1 to change, 0 to destroy. Releasing state lock. This may take a few moments... Terraform exit code: 2 ⚠️ DRIFT DETECTED — infrastructure has changed outside Terraform! Error: Process completed with exit code 1 ← workflow fails as designed
✅ Drift detection working correctly Exit code 2 captured. Workflow failed with exit 1 to alert the team. Both drift items detected: SNS topic deleted + ManualChange tag added to S3 bucket.

13 Key Takeaways

Lessons learned and common pitfalls

🔐 OIDC is the Right Way

Never store AWS access keys in GitHub secrets. OIDC gives GitHub temporary 1-hour credentials scoped to a specific repo. If intercepted, they're useless — already expired.

📋 Plan on PR = No Surprises

Posting the Terraform plan as a PR comment means reviewers see exactly what will change in AWS before approving. This prevents accidental deletions or unexpected resource changes.

💾 Saved Plan = Exact Apply

terraform plan -out=plan.tfplan saves the exact plan. terraform apply plan.tfplan applies that exact plan — not a new plan. This prevents drift between plan and apply.

🔧 terraform_wrapper: false

The setup-terraform action wraps Terraform by default and swallows exit codes. Always set terraform_wrapper: false in drift detection workflows to capture exit code 2.

⚠️ Exit Code 2 = Drift

Terraform's -detailed-exitcode flag returns exit 0 (no changes), exit 1 (error), or exit 2 (changes exist). Drift detection relies on catching exit code 2 specifically.

🌍 Always Check Your Region

Hardcoding us-east-1 when your AWS CLI is configured for ap-south-1 creates resources in the wrong region. Always verify with aws configure get region first.

Common Pitfalls

PitfallSolution
