1 Project Overview

Refactor flat infrastructure into reusable modules

Refactor the flat multi-tier infrastructure from Project 3.2 into reusable Terraform modules, then deploy the same infrastructure to dev and qa environments using those modules — with completely separate state files, separate VPCs, and zero code duplication.

Learning Objectives

#Objective
1Understand what a Terraform module is and why it exists
2Create reusable modules for VPC, EC2/ALB/ASG, and RDS
3Pass inputs into modules using variables and receive outputs
4Wire modules together — use one module's output as another's input
5Deploy the same modules to multiple environments with different configs
6Understand state isolation — each environment has its own terraform.tfstate
7Observe module namespacing in terraform state list (module.vpc.*, module.ec2.*)
8Understand the difference between flat Terraform (3.2) and modular Terraform (3.3)

Dev Environment main.tf (key section)

module "vpc" {
  source      = "../../modules/vpc"
  name_prefix = local.name_prefix    # "handson-dev"
  vpc_cidr    = "10.0.0.0/16"
  azs         = ["ap-south-1a", "ap-south-1b"]
  common_tags = local.common_tags
}

module "ec2" {
  source            = "../../modules/ec2"
  vpc_id            = module.vpc.vpc_id          # ← wired from vpc output
  public_subnet_ids = module.vpc.public_subnet_ids
  app_subnet_ids    = module.vpc.private_app_subnet_ids
  instance_type     = "t3.micro"
  desired_capacity  = 1
}

module "rds" {
  source      = "../../modules/rds"
  vpc_id      = module.vpc.vpc_id
  subnet_ids  = module.vpc.private_db_subnet_ids
  app_sg_id   = module.ec2.app_sg_id             # ← wired from ec2 output
  multi_az    = false
}

7 State Isolation

Each environment has its own terraform.tfstate

environments/ ├── dev/ │ └── terraform.tfstate ← tracks dev VPC, dev ALB, dev RDS ├── qa/ │ └── terraform.tfstate ← tracks qa VPC, qa ALB, qa RDS └── prod/ └── terraform.tfstate ← tracks prod resources (if deployed)
State isolation is critical — if both environments shared one state file, destroying dev would also destroy qa. Separate directories = separate state = safe independent operations.

8 Key Takeaways

Flat (Project 3.2) vs Modular (Project 3.3)

📦 Modules = Reusable Blueprints

Write VPC logic once in modules/vpc/. Call it from dev, qa, prod with different parameters. Change once, update everywhere.

🔗 Module Wiring

module.vpc.vpc_id → module.ec2.vpc_id. One module's output becomes another's input. Terraform resolves the dependency graph automatically.

🗂️ State Isolation

Each environment directory has its own terraform.tfstate. Destroying dev never affects qa. This is the foundation of safe multi-environment IaC.

🏷️ Module Namespacing

Resources appear as module.vpc.aws_vpc.main in state list. Makes it immediately clear which module owns each resource — essential for debugging.

🔢 cidrsubnet() Function

Subnets calculated automatically: cidrsubnet("10.0.0.0/16", 8, 1) = 10.0.1.0/24. No manual CIDR math — just change the VPC CIDR and all subnets update.

🌍 Multi-Environment Pattern

Same 3 modules deployed to dev (10.0.x.x), qa (10.1.x.x), prod (10.2.x.x). This is the industry-standard pattern for managing multiple environments.
