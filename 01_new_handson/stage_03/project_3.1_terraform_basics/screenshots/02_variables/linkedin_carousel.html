3 Ways to Pass Variables

Way 1 — .tfvars file (recommended)
terraform plan -var-file="dev.tfvars"
Bucket → dev-my-app-data-495331821583
Way 2 — Runtime override
terraform plan -var-file="dev.tfvars" -var="environment=qa"
Bucket → qa-my-app-data-495331821583 (one flag changed everything!)
Way 3 — Interactive prompt (no flags)
terraform plan
Terraform stops and asks: "Enter a value:" — avoid in CI/CD

Variable Validation

Terraform Rejects
Invalid Values

✅ ALLOWED
-var="environment=dev"
Plan proceeds normally
✅ ALLOWED
-var="environment=qa" or -var="environment=prod"
Plan proceeds normally
❌ REJECTED
-var="environment=staging"
Error: Environment must be dev, qa, or prod.
Caught BEFORE connecting to AWS ← saves time & cost
The validation block in main.tf:
validation {
  condition     = contains(["dev","qa","prod"], var.environment)
  error_message = "Environment must be dev, qa, or prod."
}

Takeaways

Key Learnings

💡
Variables make the same config work for dev, qa, and prod
💡
.tfvars files hold environment values — one file per environment
💡
-var flag overrides any value at runtime — no code changes needed
💡
Validation blocks catch invalid values before touching AWS
💡
Variables without defaults prompt interactively — avoid in CI/CD pipelines
💡
Bucket name = environment + bucket_name — meaningful, not random
