4 Output Types

In This main.tf

🔵 Simple String
output "bucket_name" { value = aws_s3_bucket.app.bucket }
Shows: outputs-demo-e63a1b07
🔴 Sensitive
output "db_password" { value = ... sensitive = true }
Shows: <sensitive> — hidden in ALL terminal output
🟣 Object
output "bucket_info" { value = { name, arn, region } }
Shows: grouped map with 3 fields
🟢 Computed URL
output "bucket_console_url" { value = "https://.../${bucket}" }
Shows: direct AWS Console link

3 Ways to Read Outputs

🔵 terraform output (all)
terraform output
Shows all outputs — sensitive still hidden
🟢 terraform output -raw (for scripts)
terraform output -raw bucket_name
outputs-demo-e63a1b07
No quotes — use directly in shell: BUCKET=$(terraform output -raw bucket_name)
🔴 terraform output -json (reveal sensitive)
terraform output -json db_password
"super-secret-password-123"
ONLY way to see sensitive value

Sensitive Outputs

Hidden Everywhere

❌ HIDDEN — terraform plan
+ db_password = (sensitive value)
Value never shown at plan stage
❌ HIDDEN — terraform apply
db_password = <sensitive>
Value never shown after apply
✓ REVEALED — terraform output -json
terraform output -json db_password
"super-secret-password-123" ← only this works
⚠️ Production tip
Never store real passwords in Terraform. Use AWS Secrets Manager instead. SSM SecureString is fine for non-critical config.

Takeaways

Key Learnings

💡
Outputs are shown after every terraform apply automatically
💡
sensitive = true hides value in plan, apply, and output commands
💡
-raw flag removes quotes — essential for shell script usage
💡
-json flag is the only way to reveal a sensitive output value
💡
Object outputs group related values — name + arn + region together
💡
SSM SecureString encrypts value with KMS automatically — no extra config
