A1. What is Infrastructure as Code (IaC)?
─────────────────────────────────────────────────────────────

Traditional Way (Before IaC):
  Engineer logs into AWS Console
  → clicks through menus manually
  → creates EC2, S3, RDS by hand
  → no record of what was done
  → cannot repeat it exactly
  → team cannot review it
  → disaster recovery = start from scratch

Infrastructure as Code (IaC):
  Engineer writes a .tf file
  → describes the desired infrastructure
  → commits to Git (version controlled)
  → team reviews via Pull Request
  → Terraform creates it automatically
  → same result every single time
  → disaster recovery = terraform apply

Definition:
  IaC is the practice of managing and provisioning
  infrastructure through machine-readable config files
  instead of manual processes.

─────────────────────────────────────────────────────────────
A2. Benefits of IaC
─────────────────────────────────────────────────────────────

  Benefit              Without IaC              With IaC
  
  Repeatability        Manual clicks            Same result every time
  Version control      No history               Every change in Git
  Team collaboration   One person knows         PR review process
  Multiple envs        Click again              Change one variable
  Disaster recovery    Rebuild manually         terraform apply
  Audit trail          Limited                  Full Git history
  Cost visibility      Surprise bills           Review before apply
  Speed                Hours of clicking        Minutes automated


A3. What is Terraform?


  Created by  : HashiCorp (2014)
  Type        : Open-source Infrastructure as Code tool
  Language    : HCL (HashiCorp Configuration Language)
  Runs on     : Your local machine or CI/CD server
  Talks to    : AWS, Azure, GCP, Kubernetes, 1000+ providers

  Terraform is NOT:
    - An AWS service (it runs locally on your machine)
    - A programming language
    - Only for AWS (works with any cloud)

  Terraform IS:
    + A CLI tool you install on your machine
    + Declarative  you describe WHAT, not HOW
    + State-aware  tracks what it created
    + Provider-based  plugins for each cloud
    + The industry standard for IaC


A4. Why Terraform Over AWS CloudFormation?


  Feature              Terraform              CloudFormation
  
  Multi-cloud          AWS + Azure + GCP      AWS only
  Language             HCL (readable)         JSON/YAML (verbose)
  Community            Huge (open source)     AWS-only community
  Modules              Terraform Registry     Limited
  Job market           Most in-demand         Limited
  Industry adoption    Standard               AWS shops only


A5. Terraform Workflow


  WRITE          PLAN           APPLY          DESTROY
                             
  Write          Preview        Create         Remove
  .tf files      changes        resources      resources
                 (safe)         in cloud       from cloud

  Step by step:

  1. terraform init
     Downloads provider plugins to .terraform/ folder
     Safe  never touches AWS

  2. terraform plan
     Reads .tf files + current state
     Shows what WILL change
     Safe  never touches AWS

  3. terraform apply
     Executes the plan
     Creates/modifies/deletes resources in AWS
     Updates terraform.tfstate
     *** TOUCHES AWS ***

  4. terraform destroy
     Removes all managed resources from AWS
     *** TOUCHES AWS  use carefully ***


A6. Terraform File Extensions


  Extension              Purpose
  
  .tf                    Main config files (resources, variables, outputs)
  .tfvars                Variable values (dev.tfvars, prod.tfvars)
  .tfstate               State file  Terraform's memory (never edit!)
  .tfstate.backup        Previous state backup (auto-created)
  .terraform/            Provider plugins folder (auto by init)
  .terraform.lock.hcl    Provider version lock file (commit to Git)

  Files to COMMIT to Git:
    YES: *.tf
    YES: *.tfvars (except ones with secrets)
    YES: .terraform.lock.hcl

  Files to NEVER commit:
    NO:  terraform.tfstate      (contains sensitive data)
    NO:  terraform.tfstate.backup
    NO:  .terraform/            (large, auto-downloaded)
    NO:  *.tfvars with passwords


A7. Terraform Core Concepts


  Concept          Description
  
  Provider         Plugin that talks to a cloud API (AWS, Azure)
  Resource         An infrastructure object to create (S3, EC2)
  Variable         Input parameter  makes configs reusable
  Output           Value exported after apply (IP, ARN, URL)
  State            terraform.tfstate  tracks what Terraform manages
  Module           Reusable group of resources (like a function)
  Data source      Read existing resources (don't create them)
  Local            Computed value derived from other values
  Backend          Where state is stored (local or S3 + DynamoDB)


A8. Common Terraform Commands


  Command                          Purpose
  
  terraform init                   Initialize  download providers
  terraform plan                   Preview changes (safe, no AWS)
  terraform apply                  Create/update resources in AWS
  terraform destroy                Delete all managed resources
  terraform output                 Show output values
  terraform output -raw <name>     Get clean value for scripts
  terraform output -json <name>    Get JSON (reveals sensitive)
  terraform state list             List all tracked resources
  terraform state show <resource>  Show details of one resource
  terraform fmt                    Auto-format .tf files
  terraform validate               Check syntax without connecting
  terraform refresh                Sync state with real AWS


A9. Terraform Recommended Folder Structure


  project/
   main.tf           resources (EC2, S3, RDS, etc.)
   variables.tf      variable declarations
   outputs.tf        output declarations
   locals.tf         local computed values
   versions.tf       required_providers + required_version
   backend.tf        remote state config (S3 + DynamoDB)
   dev.tfvars        dev environment values
   qa.tfvars         qa environment values
   prod.tfvars       prod environment values
   modules/
       vpc/
       ec2/
       rds/

  Note: For small projects, a single main.tf is fine.
  Split into separate files as the project grows.


A10. Real-World Terraform Workflow (Industry)


  Developer's laptop              CI/CD Pipeline (GitHub Actions)
                
  1. Write .tf files              5. PR opened
  2. terraform fmt                   pipeline runs:
  3. terraform validate               terraform fmt -check
  4. git push feature branch          terraform validate
                                      terraform plan
                                      posts plan as PR comment

                                6. Team reviews plan in PR
                                   approves or requests changes

                                7. Merge to main
                                   pipeline runs:
                                   terraform apply -auto-approve
                                   infrastructure updated

                                8. Drift detection (nightly)
                                   terraform plan runs scheduled
                                   alerts if manual changes found

PART D  THE main.tf FILE


  File location:
    D:\1.projects\AI\my-aws\01_new_handson\stage_03\
    project_3.1_terraform_basics\01_hello_terraform\main.tf

  File contents:

    # 01_hello_terraform/main.tf
    # Your very first Terraform resource  an S3 bucket.

    terraform {
      required_providers {
        aws = {
          source  = "hashicorp/aws"
          version = "~> 5.0"
        }
        random = {
          source  = "hashicorp/random"
          version = "~> 3.0"
        }
      }
      required_version = ">= 1.5.0"
    }

    provider "aws" {
      region = "ap-south-1"
    }

    resource "aws_s3_bucket" "hello" {
      bucket = "hello-terraform-${random_id.suffix.hex}"
      tags = {
        Name      = "hello-terraform"
        Project   = "handson"
        Stage     = "stage-03"
        ManagedBy = "terraform"
      }
    }

    resource "random_id" "suffix" {
      byte_length = 4
    }

    resource "aws_s3_bucket_versioning" "hello" {
      bucket = aws_s3_bucket.hello.id
      versioning_configuration {
        status = "Enabled"
      }
    }

    output "bucket_name" {
      description = "The name of the S3 bucket"
      value       = aws_s3_bucket.hello.bucket
    }

    output "bucket_arn" {
      description = "The ARN of the S3 bucket"
      value       = aws_s3_bucket.hello.arn
    }

  Bug fixed before running:
    Issue: random provider was missing from required_providers
    Fix:   Added random = { source = "hashicorp/random" version = "~> 3.0" }
    Issue: Region was us-east-1
    Fix:   Changed to ap-south-1 (Mumbai) to match IAM user region

STEP 2  terraform plan


  Command:
    terraform plan

  Key output:
    + aws_s3_bucket.hello            will be created
    + aws_s3_bucket_versioning.hello will be created
    + random_id.suffix               will be created

    Plan: 3 to add, 0 to change, 0 to destroy.

    Changes to Outputs:
    + bucket_arn  = (known after apply)
    + bucket_name = (known after apply)

  What "(known after apply)" means:
    AWS will generate these values when the resource is created.
    Terraform doesn't know them yet  that's normal.
    Example: bucket name will be "hello-terraform-9273bec5" after apply.

  What happened:
    Terraform connected to AWS and checked current state
    Showed exactly what would be created
    NOTHING created in AWS yet  safe preview only

  Key learning:
    terraform plan is ALWAYS safe.
    It never creates, modifies, or deletes anything.
    Always run plan before apply.

STEP 4  terraform state list


  Command:
    terraform state list

  Output received:
    aws_s3_bucket.hello
    aws_s3_bucket_versioning.hello
    random_id.suffix

  What this shows:
    Terraform is tracking 3 resources in its state file.
    State file = terraform.tfstate in the working directory.
    This is Terraform's "memory" of what it created.

  Key learning:
    The state file is the source of truth for Terraform.
    Never edit terraform.tfstate manually.
    If state is lost, Terraform loses track of resources.
