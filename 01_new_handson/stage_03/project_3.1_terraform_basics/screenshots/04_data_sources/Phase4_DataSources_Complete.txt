PART A  TOOL THEORY: TERRAFORM DATA SOURCES


A1. What Are Data Sources?


  Data sources allow Terraform to READ existing AWS resources
  without creating, modifying, or deleting them.

  They solve a critical problem:
    Without data sources: ami = "ami-0abcd1234"   hardcoded, breaks when AMI updates
    With data sources:    ami = data.aws_ami.amazon_linux.id   always latest

  Key rule:
    Resources  CREATE infrastructure (cost money)
    Data sources  READ infrastructure (always free)


A2. Why Data Sources Matter


  Problem 1  Hardcoded AMI IDs
    AMI IDs are region-specific and change when AWS releases updates.
    Hardcoding ami-0abcd1234 will break when that AMI is deprecated.
    Solution: data "aws_ami" always fetches the latest matching AMI.

  Problem 2  Hardcoded Account IDs
    Your account ID (495331821583) should not be in code.
    Other team members have different account IDs.
    Solution: data "aws_caller_identity" reads it dynamically.

  Problem 3  Hardcoded VPC/Subnet IDs
    VPC IDs differ between accounts and regions.
    Solution: data "aws_vpc" and data "aws_subnets" read them dynamically.

  Problem 4  Referencing resources not in this Terraform config
    Some resources are created manually or by another team.
    Solution: data sources reference them without importing into state.


A3. Data Source Syntax


  data "aws_ami" "amazon_linux" {
    most_recent = true
    owners      = ["amazon"]

    filter {
      name   = "name"
      values = ["al2023-ami-*-x86_64"]
    }
  }

  Parts explained:
    data          : keyword (not resource)
    "aws_ami"     : data source type (provider-specific)
    "amazon_linux": local name (used to reference it)
    most_recent   : get the newest matching AMI
    owners        : only AMIs owned by Amazon
    filter        : narrow down by name pattern

  How to reference it:
    data.aws_ami.amazon_linux.id      the AMI ID
    data.aws_ami.amazon_linux.name    the full AMI name


A4. Data Sources vs Resources


  Feature              Resource                    Data Source
  
  Keyword              resource                    data
  Creates AWS object   YES                         NO
  Costs money          YES (if resource costs)     NO (always free)
  Shows in plan        + create                    Reading...
  In state file        YES                         YES (cached)
  Destroyable          YES (terraform destroy)     NO (nothing to destroy)
  Prefix in code       aws_s3_bucket.name          data.aws_s3_bucket.name


A5. Common Data Sources


  Data Source                    What it reads
  
  aws_ami                        Latest AMI matching filters
  aws_caller_identity            Current account ID, user ARN
  aws_region                     Current region name
  aws_vpc                        VPC by ID, name, or default=true
  aws_subnets                    Subnets filtered by VPC, tags, AZ
  aws_availability_zones         Available AZs in current region
  aws_s3_bucket                  Existing S3 bucket details
  aws_iam_role                   Existing IAM role ARN
  aws_security_group             Existing security group
  aws_route53_zone               Existing hosted zone ID
  aws_secretsmanager_secret      Secret ARN from Secrets Manager
  aws_ssm_parameter              Parameter value from SSM


A6. Real-World Use Cases


  Use case 1  EC2 with latest AMI (never hardcode AMI IDs):
    resource "aws_instance" "web" {
      ami           = data.aws_ami.amazon_linux.id   always latest
      instance_type = "t3.micro"
      subnet_id     = data.aws_subnets.default.ids[0]
    }

  Use case 2  S3 bucket name with account ID:
    resource "aws_s3_bucket" "data" {
      bucket = "my-data-${data.aws_caller_identity.current.account_id}"
    }

  Use case 3  Reference existing VPC for new resources:
    resource "aws_security_group" "app" {
      vpc_id = data.aws_vpc.default.id
    }

  Use case 4  Get secret from Secrets Manager:
    data "aws_secretsmanager_secret_version" "db_pass" {
      secret_id = "prod/db/password"
    }
    resource "aws_db_instance" "main" {
      password = data.aws_secretsmanager_secret_version.db_pass.secret_string
    }


A7. Common Terraform Commands (Data Sources Context)


  Command              Purpose
  
  terraform init       Download providers
  terraform plan       Reads data sources + shows outputs (no AWS changes)
  terraform apply      Reads data sources + saves outputs to state
  terraform output     Show all output values
  terraform output -raw <name>   Get clean value for scripts

PART D  THE main.tf FILE


  File location:
    D:\1.projects\AI\my-aws\01_new_handson\stage_03\
    project_3.1_terraform_basics\04_data_sources\main.tf

  File contents:

    terraform {
      required_providers {
        aws = { source = "hashicorp/aws", version = "~> 5.0" }
      }
    }

    provider "aws" { region = "ap-south-1" }

    # Data Source 1: Latest Amazon Linux 2023 AMI
    data "aws_ami" "amazon_linux" {
      most_recent = true
      owners      = ["amazon"]
      filter {
        name   = "name"
        values = ["al2023-ami-*-x86_64"]
      }
      filter {
        name   = "virtualization-type"
        values = ["hvm"]
      }
    }

    # Data Source 2: Current AWS Account & Region
    data "aws_caller_identity" "current" {}
    data "aws_region" "current" {}

    # Data Source 3: Default VPC
    data "aws_vpc" "default" {
      default = true
    }

    # Data Source 4: Subnets in Default VPC
    data "aws_subnets" "default" {
      filter {
        name   = "vpc-id"
        values = [data.aws_vpc.default.id]
      }
    }

    # Data Source 5: Availability Zones
    data "aws_availability_zones" "available" {
      state = "available"
    }

    output "ami_id"            { value = data.aws_ami.amazon_linux.id }
    output "ami_name"          { value = data.aws_ami.amazon_linux.name }
    output "account_id"        { value = data.aws_caller_identity.current.account_id }
    output "current_region"    { value = data.aws_region.current.name }
    output "default_vpc_id"    { value = data.aws_vpc.default.id }
    output "default_vpc_cidr"  { value = data.aws_vpc.default.cidr_block }
    output "default_subnet_ids"{ value = data.aws_subnets.default.ids }
    output "availability_zones"{ value = data.aws_availability_zones.available.names }
    output "useful_for_ec2"    {
      value = "ami = ${data.aws_ami.amazon_linux.id} | subnet_id = ${data.aws_subnets.default.ids[0]}"
    }

  Note: EC2 instance was intentionally removed from this phase.
  Data sources alone demonstrate the concept at zero cost.
  The useful_for_ec2 output shows how you would use these in Project 3.2.
